# ISSUE-PIN-LEAK.md — تحليل آلية توليد PIN اليومي
> تاريخ التحليل: 2026-02-22 | الملف المصدر: `love-api/api/v1.js`

---

## 1. تحليل دالة `generateDailyPIN`

يتم توليد PIN الدخول للعيادة في دالة `generateDailyPIN`. الآلية كالتالي:

1.  يتم استخدام تاريخ اليوم الحالي ومعرف العيادة (`clinicId`) كمدخلات.
2.  يتم استخدام مفتاح سري (`PIN_SECRET`) من متغيرات البيئة، وفي حال عدم وجوده، يتم استخدام قيمة افتراضية ثابتة (`'mmc-mms-secret-2026'`).
3.  يتم إنشاء HMAC-SHA256 hash بناءً على المدخلات والمفتاح السري.
4.  يتم تحويل جزء من الـ hash إلى رقم PIN مكون من خانتين (10-99).

```javascript
// love-api/api/v1.js (السطور 54-60)

function generateDailyPIN(clinicId) {
  const today = new Date().toISOString().split('T')[0];
  const secret = process.env.PIN_SECRET || 'mmc-mms-secret-2026'; // <-- Hardcoded fallback
  const hash = crypto.createHmac('sha256', secret).update(`${clinicId}-${today}`).digest('hex');
  // PIN من رقمين فقط (10-99) ويتغير يومياً تلقائياً
  return (parseInt(hash.substring(0, 8), 16) % 90 + 10).toString();
}
```

## 2. تحديد مخاطر تسريب PIN

**نعم، يوجد خطر تسريب PIN.**

المشكلة الرئيسية تكمن في أن **الـ PIN يمكن توقعه (is predictable)**. بما أن الخوارزمية معروفة (موجودة في الكود)، فإن أي شخص لديه إمكانية الوصول إلى المفتاح السري (`PIN_SECRET`) يمكنه توليد الـ PIN لأي عيادة في أي يوم.

وجود **قيمة افتراضية ثابتة (`'mmc-mms-secret-2026'`)** يزيد من خطورة المشكلة بشكل كبير. إذا لم يتم تعيين متغير البيئة `PIN_SECRET` في بيئة الإنتاج، فسيتم استخدام هذا المفتاح الثابت، مما يجعله هدفاً سهلاً للمهاجمين.

## 3. هل يتم تخزين الـ PIN في قاعدة البيانات؟

**لا.** الـ PIN يتم توليده ديناميكياً عند الطلب عبر نقطة النهاية `/api/v1/clinics/:id/pin` ولا يتم تخزينه في قاعدة البيانات. يتم التحقق منه بمقارنة القيمة التي أدخلها المستخدم مع القيمة التي تم توليدها في نفس اللحظة.

## 4. الاستنتاج

آلية توليد الـ PIN الحالية غير آمنة بسبب اعتمادها على مفتاح سري ثابت يمكن كشفه، مما يسمح بتوليد PINs صالحة خارج النظام. يجب تغيير هذه الآلية بالكامل. الحل المقترح هو:

1.  **توليد PIN عشوائي تماماً** لكل مراجع عند دخوله الطابور.
2.  **تخزين الـ PIN المؤقت** في سجل المراجع في جدول `unified_queue`.
3.  **التحقق من الـ PIN** بمقارنة القيمة المدخلة مع القيمة المخزنة في قاعدة البيانات.
4.  **حذف الـ PIN** أو إبطاله فور استخدامه بنجاح.

هذا يضمن أن كل PIN فريد، مؤقت، وغير قابل للتوقع.
