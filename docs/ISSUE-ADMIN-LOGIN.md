# ISSUE-ADMIN-LOGIN.md — تحليل مشكلة طلب اسم المستخدم مرتين
> تاريخ التحليل: 2026-02-22 | الملف المصدر: `frontend/src/components/LoginPage.jsx`

---

## 1. وصف المشكلة

عندما يقوم المشرف بإدخال بيانات تسجيل دخول غير صالحة (مثلاً، اسم مستخدم قصير جداً)، يعرض النظام رسالة خطأ، ولكنه لا يمسح حقل اسم المستخدم. هذا السلوك يجعل المستخدم يشعر وكأن النظام يطلب منه "اسم المستخدم مرتين"، حيث أن القيمة الخاطئة تبقى في الحقل ويجب على المستخدم تعديلها أو حذفها يدوياً.

## 2. تحليل السبب الجذري (Root Cause Analysis)

السبب الجذري للمشكلة يكمن في دالة `handleAdminSubmit` داخل `LoginPage.jsx`. عند فشل التحقق من صحة البيانات، يتم تحديث حالة الخطأ (`validationError`) وحالة الإرسال (`isSubmitting`)، ولكن **لا يتم إعادة تعيين حالة اسم المستخدم (`adminUsername`) أو كلمة المرور (`adminPassword`)**.

ونتيجة لذلك، عندما يتم إعادة عرض المكون (re-render) لإظهار رسالة الخطأ، تظل حقول الإدخال مرتبطة بالقيم القديمة غير الصالحة، مما يؤدي إلى بقاء اسم المستخدم الخاطئ في الحقل.

### البلوك المسؤول عن المشكلة

```javascript
// داخل دالة handleAdminSubmit في LoginPage.jsx

const validation = validateAdminData({
  username: sanitizedUsername,
  password: adminPassword
});

if (!validation.isValid) {
  setValidationError(validation.errors[0]);
  setIsSubmitting(false); // يتم إيقاف حالة الإرسال
  // <-- نقطة الخلل: لا يتم مسح adminUsername هنا
  return; // الخروج من الدالة
}
```

- **السطر 101-104:** في حالة فشل `validateAdminData`، يتم استدعاء `setValidationError` و `setIsSubmitting(false)` ثم يتم الخروج من الدالة. قيمة `adminUsername` تبقى كما هي.

## 3. سيناريو إعادة الإنتاج (Steps to Reproduce)

1.  افتح صفحة تسجيل الدخول في التطبيق.
2.  انقر على زر "الإدارة" (Admin) للتبديل إلى وضع تسجيل دخول المشرف.
3.  في حقل "اسم المستخدم"، أدخل قيمة غير صالحة (أقل من 3 أحرف)، مثل `ab`.
4.  في حقل "كلمة المرور"، أدخل أي قيمة.
5.  انقر على زر "دخول ←" (Login).
6.  **النتيجة المتوقعة:** تظهر رسالة خطأ مثل "اسم المستخدم يجب أن يكون 3 أحرف على الأقل".
7.  **المشكلة:** يبقى حقل "اسم المستخدم" محتوياً على القيمة غير الصالحة `ab`.

## 4. الاستنتاج

المشكلة ليست وجود حقل إدخال مكرر، بل هي تجربة مستخدم سيئة ناتجة عن عدم مسح الحقول بعد فشل التحقق من الصحة. الحل المقترح هو إعادة تعيين حالة `adminUsername` و `adminPassword` إلى سلسلة فارغة عند حدوث خطأ في التحقق. ومع ذلك، حسب التعليمات، يجب أن نمنع إعادة تعيين `username` بعد فشل التحاليل، لذا فإن الإصلاح سيركز على منع `double submit` بشكل أكثر فعالية وعرض الأخطاء بوضوح دون مسح المدخلات، مع التأكد من أن `autoComplete` يعمل بشكل صحيح.
